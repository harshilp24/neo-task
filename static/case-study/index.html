Task 1: Clarifying questions

The brief

List everything you would need clarified before you could write accurate documentation from the extract. For each item, state the assumption you took in order to complete the document.

I compared the PRD with the Tracks screen on neo.work and listed every gap or conflict, with the assumption I used for each. Where a gap could lead to lost data, I assumed the safer behaviour and added a warning to the docs.

Task 2: The Tracks docs

The brief

Write three pieces on the same feature: a user-facing feature document for someone using the feature for the first time, a how-to guide for someone with a specific task in hand, and a release note for an existing user scanning what changed.

I wrote the docs as a real docs site instead of a single document. Each page covers one kind of need (Diátaxis). Steps and rules appear on one page, and other pages link to them.

Supporting pages

  • Tracks reference ↗: every status, action, permission and offline rule.
  • Troubleshoot Tracks ↗: ten issues, each with its cause and solution.
  • Tasket overview ↗: what Tasket is, with links to every Tracks page.

Also in the site

  • Copy page on every page: copy it as Markdown, view the Markdown, or open it in ChatGPT or Claude.
  • Was this page helpful? at the end of every page, with a thumbs up or down.
  • Search wired for Algolia DocSearch, opened with ⌘K.
  • Changelog by month, with product and type filters.
  • Sidebar grouped by task, then by page type.
  • Build checks: the site won't build with a broken link or anchor.

Choices I made

  • UI labels follow the real screen. The UI says Pending where the PRD says In Progress, so the docs say Pending.
  • Warnings before permanent actions. Deleting a track and turning Tracks off each have a warning above the steps.
  • Descriptions answer the question. Each page's meta description answers its main question in one line, for search engines and AI assistants.

Task 3: The write-docs skill

The brief

Build a reusable skill file that produces a first draft of those same three article types from any PRD and its supporting artefacts, not just this one.

write-docs is a folder of plain Markdown that any AI assistant or writer can follow. Give it a PRD and any screens, and it drafts a feature document, a how-to guide and a release note, plus the clarifying questions and a checklist report. It can also write the full doc set, or update existing pages when the PRD changes.

Write-docs skill

An agent skill for drafting Neo product documentation from a PRD. Give it a PRD and any screens or tickets, and it produces first drafts of every page a feature needs, plus a list of questions the PRD leaves open.

Architecture overview

The skill handles task-specific jobs through workflows, and reuses shared modules and framework rules for everything else.

Execution flow
SKILL.md (routing)
 └─> workflows/  (one per kind of job)
      ├─> modules/  (PRD analysis, page planning, doc contracts, content generation)
      │    └─> framework/  (Diátaxis, style and tone, linking, callouts, files, personas)
      └─> quality/checklist.md  (shared checks)

How to run it

  1. Give it the PRD, plus any screenshots or tickets.
  2. Ask: Use write-docs to draft the docs for this PRD.
  3. Review the pages, the release note, the clarifying questions and the checklist report.
