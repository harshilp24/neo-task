# Contract: feature document

Used by [../../workflows/three_pieces.md](../../workflows/three_pieces.md). One page that introduces a feature and gets a first-time reader set up. In the full doc set, the [tutorial](tutorial.md) and [explanation](explanation.md) split this between them.

**Title:** Get started with <Feature>
**Reader:** using the feature for the first time.
**Promise:** they know what it is, have it set up, and know the rules that could cost them data.

## Front matter

Same as the tutorial: an answer-first `description`, `tags: [<product>, <feature>, tutorial]`, `keywords`, `toc_max_heading_level: 2`.

## Sections, in order

1. **Intro** (no heading): what the feature is in two lines, then "In this guide, you <outcome>."
2. **Before you begin**: "Make sure you have:" with access, connection and anything to prepare.
3. **Set up <Feature>**: numbered steps, one action each, examples inside the step that say why.
4. **How it works**: three to five bullets on the model, such as statuses and where they show. No steps.
5. **Good to know**: who can do what, what works offline, and every action that can't be undone. One line each.
6. **Next steps**: link to the how-to guide.

## Rules

- Everything traces to the PRD, the screens, or a clarifying question.
- Warnings for anything that can't be undone, before the step that does it.
