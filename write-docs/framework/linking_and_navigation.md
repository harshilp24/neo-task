# Linking and navigation

How pages connect and where they sit in the sidebar.

## Sidebar: by job, then by type

The sidebar is organised by what the reader is trying to do, then by Diátaxis type. New features slot into a job area by goal, not under their own name.

```
<Product> overview
GET STARTED          tutorials, one per feature
<JOB AREA>           how-to guides, named for the job (for example "Run work across teams")
CONCEPTS             explanation pages
REFERENCE            reference pages
HELP                 FAQ, then troubleshooting
```

- **Adding a second feature.** Put each new page into the existing section for its type: its tutorial under **Get started** next to the others, its reference under **Reference**, and so on. Put its guide in the job area whose goal it serves; add a new job area only if none fits. Never add a section named after the feature.
- **One entry per page.** Never add a second entry that jumps to a section of a page that's already listed.
- **Job areas** are named for a user goal: "Plan work", "Run work across teams", "Work with guests", "Administer". Not for a feature or a team.
- **Labels** in the sidebar can be shorter than the page title, but must mean the same thing.

The sidebar lives in `sidebars.js`. Each section is a category with an icon class, `collapsible: true` and `collapsed: false`: it shows a chevron and starts open.

## Breadcrumb

Each page shows **Home › <Product> › <sidebar section>** above the title, with the section in the accent colour. The overview shows **Home › <Product>**. It's generated by `src/theme/DocItem/Content`; don't write it into the page.

## Links in text

- Link to the page that owns a fact instead of repeating it: "To set up Tracks for the first time, start with [Get started with Tracks](…)."
- Use relative links to `.mdx` files inside `docs/`, so the build checks them.
- Link text is the page title or a clear action. Never "click here" or "this page".
- In lists of links, use `[Title](link): what it gets you`.

## Required links per page type

| Page type | Must link to |
|---|---|
| Tutorial | The explanation (on the feature name in the intro); explanation, guide and FAQ in *Next steps* |
| How-to guide | The explanation (in the intro); FAQ, reference and troubleshooting in *See also* |
| Explanation | The tutorial (in the intro); tutorial, guide, FAQ and reference in *See also* |
| Reference | The tutorial, guide and FAQ, in the intro |
| FAQ | Troubleshooting (in the intro); reference and troubleshooting in *See also* |
| Troubleshooting | The FAQ and reference (in the intro), and the page that owns each fix |
| Product overview | Every page of the feature, as cards |
| Release note | The explanation, as "Learn about <feature> →" |

## Anchors

Link to a section with its heading's anchor, for example `faq.mdx#how-do-i-turn-off-tracks`. If you rename a heading, search the repo for its old anchor. The build fails on broken anchors.
